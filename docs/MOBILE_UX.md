# 手机体验设计

## 当前交互

- 首页只承担选择动作、确认目标和开始训练，保持一屏；方向、语音、骨架、使用说明及记录分别放进原生弹窗。
- 参考 iOS 的系统字体、浅灰背景、蓝色主操作、分组圆角、分段控件和底部面板，避免伪录像装饰。
- 用户确认动作后进入独立训练层；相机容器占可用网页视口的 90%，底部保留主要操作。系统状态栏和浏览器工具栏不属于网页可控制区域。
- 视频使用 contain 保留完整视野；相机容器的面积不等于视频内容铺满的面积，传感器宽高比不同时可能留黑边。
- 计数、时间与一个纠错提示浮在画面上。训练中打开设置先暂停；继续时重新检查站位，不自动恢复摄像头。
- 主要操作触摸区至少 44px；考虑底部安全区、横屏、数字键盘和系统减少动画偏好。放大字体仍可使用，说明与设置面板允许内部滚动。
- 首页不打开摄像头；暂停、休息、结束、后台或取消请求时释放采集与模型实例。模型文件字节在当前页面内缓存，减少继续训练时重复下载；刷新后缓存清空。

## 已验证

见 [布局测量数据](../evaluation/mobile-layout.json)：Chromium 模拟 320×568、390×844、430×932 和 844×390。首页 scrollHeight 等于视口高度、scrollWidth 等于视口宽度，开始按钮可见；训练层相机高度占比约 90%（像素取整有微小误差），主要按钮高 44px。

浏览器检查了动作选择、目标设置与摘要、动作专属说明；模拟资源测试覆盖打开设置时自动暂停、加载取消、后台与结束等路径。布局测量中通过打开原生训练弹窗检查几何尺寸，没有开启摄像头。截图为默认首页。

## 下一步优先验证

1. 用真实 iPhone Safari 和 Android Chrome 测量从点击开始到首次有效计数的时间，重点观察首次权限、弱网、继续训练及横竖屏切换。
2. 在固定亮度、机位和训练时长下对比温度、电量、帧延迟、漏计与误计；根据结果在流畅度和负载间调整推理频率，而非仅凭桌面测试判断节能。
3. 测试离手机约两米时，用户能否听懂或看懂单条提示；优化语音节流、音量与识别丢失后的恢复。
4. 测试系统大字体、VoiceOver、TalkBack、来电和锁屏返回。极端字号以可访问和不裁切内容为先，必要时允许滚动，不通过缩小文字强行塞屏。

真实手机的温度、电量、摄像头识别效果和辅助功能体验尚未完成验收。
